# 已知问题与坑（接口路线）

## 1. 排序必须是「最新」

- **现象**：群组页默认「最相关」排序，滚动很深也拿不到早期帖子（实测 2025 全年只 18 帖）。
- **处理**：打开页面时 URL 必须带 `?sorting_setting=CHRONOLOGICAL`，`variables.sortingSetting` 也是 `CHRONOLOGICAL`。

## 2. 响应是 JSONL，不是单个 JSON

- **现象**：`json.loads(整个响应)` 报 `Extra data`。
- **处理**：按行解析，再按每行的 `path` 合并到同一棵树。
- **坑**：`page_info` 那一行的 `path` 是 `["node","group_feed"]`，若直接赋值会把已有的 `edges` 整个覆盖掉，必须做 dict 合并。

## 3. 零互动 ≠ null

- **现象**：零评论/零点赞的帖子，`aria-label` 和互动栏都没数字，容易被当成「未获取」。
- **处理**：按钮存在但无数字即判 0。接口路径直接有 `reaction_count.count = 0`，不存在这个问题。

## 4. 分享数为 0 时界面不显示

- 接口里 `share_count.count` 始终存在（含 0），比 DOM 路径可靠。

## 5. 推荐内容混入

- **现象**：feed 会插入非本组帖子。
- **处理**：只保留 `permalink_url` 含 `/groups/2201697719848708/` 的节点。

## 6. 标签页残留

- **现象**：反复 `new_tab()` 被中断会堆积标签页，几十个后 DrissionPage 连接超时（`Page.getFrameTree` timeout）。
- **处理**：复用已有群组标签页；清理用 CDP：
  ```bash
  curl -s http://127.0.0.1:9227/json/list
  curl -s http://127.0.0.1:9227/json/close/<targetId>
  ```

## 7. 接口重放不可行

- **现象**：用捕获的请求重放，`cursor` 置空返回 `group_feed: null` + `field_exception`。
- **原因**：cursor 是 protobuf base64，必须来自上一页响应。
- **结论**：只做监听，不构造请求。

## 8. 滚动节奏

- 一次 `scrollTo(0, scrollHeight)` 会跳过中间页，导致漏请求。
- 用 `scrollBy(0, 1500~2000)` + 1.5–2.5 秒停顿；实测 8 次滚动 → 9 个请求，0 丢失。

## 9. doc_id 会变

- feed 操作当前是 `28808848798817508`，FB 前端更新后会换。
- 不要硬编码为唯一入口，优先从监听到的请求里动态获取。

## 10. 图片链接会过期

- CDN 链接带签名，几小时后失效。需要留图必须采集时下载。
